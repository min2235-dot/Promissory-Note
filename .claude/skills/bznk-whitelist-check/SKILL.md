# BZNK 白名單快速審查判定

## 用途

使用者只需給借款人姓名/公司名稱（若有本次申請金額更好），此技能自動跑完下面
四個維度的檢查，產出「這件案子可否走快速通道」的分級結論，減少人工逐案翻歷史
資料的時間。

## 前置確認：工具是否可用

先確認以下工具是否已在工具清單裡：
- Bznk MCP：`get_user_loan_summary`、`get_all_items`、`get_user_profile`、
  `get_business_identity`
- sumto：`list_suppliers`、`check_supplier`、`add_supplier`

如果呼叫時出現 `Tool not found`，用 `tool_search` 搜尋 `Bznk` 或 `sumto`
重新載入，不用跟使用者多解釋細節，重試成功就直接繼續。

## 執行步驟

### 1. 找到借款人

呼叫 `Bznk MCP:get_user_loan_summary`，`keyword` 帶使用者輸入的公司名稱/人名。

- `matched_user_count == 0`：告知找不到符合的會員，不往下查（新客戶可能還沒
  註冊或名稱有誤，請使用者確認）。
- `matched_user_count > 1`：列出所有比對到的公司名稱＋負責人，請使用者指定
  是哪一家，等回覆後才繼續。
- `matched_user_count == 1`：記下 `user_id`、`company_names`、
  `promissory_note_info`、`total_remaining_principal`。

### 2. 撈出這個借款人的歷史案件

呼叫 `Bznk MCP:get_all_items`，`filters: {"user_id_eq": <user_id>}`，
`per_page: 100`。若 `total_pages > 1`，把所有頁面抓完。

若完全沒有歷史案件（`total_count == 0`）：視為**新客戶**，跳到步驟 6 直接
標記 🟡（首次往來，無歷史信用資料可判斷），但仍要做步驟 5、7 的企業認證與
sumto 檢查。

### 3. 維度一：歷史信用（一票否決優先檢查）

把所有案件依 `status` 分類：

| 分類 | status | 意義 |
|---|---|---|
| 正常結案 | `Finish/6`、`Cashed/9` | 正向歷史 |
| 進行中 | `Active/2`、`InTransaction/3`、`Pending/0`、`WaitingForApproval/1`、`AddDoc/7` | 中性，不算負面也不算完整正向 |
| **負面（一票否決）** | `Reject/5`（婉拒）、`Return/8`（退票） | 任何一筆出現，直接判定 🔴 完整審查 |

- 只要出現任何 `Reject` 或 `Return`，**直接判定 🔴**，不用再往下跑其他維度，
  在結論列出這幾筆的 `label_id`。
- 否則統計「正常結案」筆數：
  - `>= 3` 筆 → 歷史信用足夠
  - `1-2` 筆 → 歷史偏薄，標記需留意
  - `0` 筆（但有進行中案件）→ 視同信用資料不足，標記 🟡

### 4. 維度二：目前曝險比例

用步驟 1 拿到的 `total_remaining_principal` 除以 `promissory_note_info`
（本票額度）：

- `promissory_note_info` 為 `null` → 標記「無本票額度可比對，需人工確認
  額度上限」，此維度算未過。
- 曝險比例 `<= 70%` → 安全範圍。
- 曝險比例 `> 70%` → 標記需人工複核（額度快滿，加上這筆新案件後可能超限）。

（70% 是預設參考門檻，如果 BZNK 內部有正式的額度上限政策，請以使用者說的
數字為準。）

### 5. 維度三：本次金額是否異常放大

如果使用者有提供本次申請金額，用步驟 2 撈到的歷史案件（`cheque.cheque_amount`
優先，沒有則用 `expected_loan_amount`）取歷史最大值：

- 本次金額 `<=` 歷史最大值 × 1.5 → 正常。
- 本次金額 `>` 歷史最大值 × 1.5 → 標記「金額異常放大，需人工複核合理性」。

如果使用者沒給金額，此維度先跳過，在結論裡提醒「未提供本次金額，無法比對
異常放大」。

### 6. 維度四：第三方監控燈號（sumto）＋ 企業認證狀態

- 取得該公司統一編號：從 `get_user_loan_summary` 回傳案件的
  `business_identity_id` 呼叫 `Bznk MCP:get_business_identity` 拿
  `business_vat_no` 與 `status`（企業認證狀態）。
  - `status != 通過驗證` → 標記「企業身分尚未完成認證，建議先完成認證
    才能列入快速通道」（視為降級條件，不到一票否決但足以擋 🟢）。
- 用 `business_vat_no` 呼叫 `sumto:list_suppliers` 看是否已在監控名單：
  - 不在名單 → 呼叫 `sumto:add_supplier` 加入，並在結論註明「已新加入
    監控，明天起才會有燈號資料，本次判斷僅能以現有其他維度為準」。
  - 已在名單 → 看燈號：
    - `green` → 安全。
    - `amber` → 標記需人工留意（一般工商/法院/動產異動）。
    - `red` → **直接判定 🔴 完整審查**（高風險異動）。

### 7. 應收帳款案件的額外提醒

如果該借款人的案件裡有 `item_type: cheque` 且 `sub_type: tt`（應收帳款融資），
真正的還款來源是發票方（付款方）而不是借款人本身。目前工具無法直接用發票方
統編篩選歷史案件，所以：

- 若使用者提供了發票方統編，可另外對發票方統編跑一次 sumto
  （`list_suppliers`/`check_supplier`/`add_supplier`），邏輯同步驟 6。
- 若使用者想看發票方過去在其他案件的兌現表現，提醒可另外執行「未兌現票面
  金額查詢」技能來人工核對，這裡不自動展開，避免誤判。

### 8. 補充資料來源：Google Drive 內部名單（若已連接）

若目前環境已連接 Google Drive connector（例如 Claude Code 有串接 Google
Drive），在做出最終結論前，多做這一步比對：

- 搜尋 Drive 是否有維護「內部黑名單」「婉拒名單」「風控名單」等試算表
  （檔名或內容關鍵字包含「黑名單」、「婉拒」、「風控」、「watchlist」之類）。
- 找到檔案就用借款人姓名/公司名稱、統一編號去比對：
  - 出現在名單中 → 視同一票否決，直接判定 🔴，在結論註明「依 Drive 內部
    名單《檔名》判定」，並附上該檔案的更新日期（若有）供覆核者確認資料
    是否過期。
  - 沒出現在名單中 → 不影響結果，正常依步驟 3-6 的結論。
- 找不到任何相關檔案，或 Google Drive 尚未連接：直接略過此步驟，不用向
  使用者說明細節，也不影響原本四維度判斷流程正常運作——這一步是額外的
  補強比對，不是必要條件。

### 9. 綜合結論分級

- 🟢 **建議快速通道**：無一票否決條件、正常結案 ≥3 筆、曝險比例 ≤70%、
  金額未異常放大、企業已認證、sumto 燈號 green（或穩定監控中無異動）、
  且未出現在 Drive 內部名單中。
- 🟡 **建議人工覆核**：任一維度未過但沒有觸發一票否決（例如歷史偏薄、
  曝險偏高、金額放大、企業未認證、sumto 剛加入監控、新客戶無歷史）。
  逐項列出未過的維度與原因。
- 🔴 **需完整審查**：出現任何一票否決條件（退票/婉拒紀錄、sumto red燈號、
  或列在 Drive 內部黑名單中）。列出否決依據。

## 輸出格式（固定順序）

1. 借款人全名（user_id: xxxx）
2. 四維度檢查結果表格：

   | 維度 | 結果 | 依據 |
   |---|---|---|
   | 歷史信用 | ✅/⚠️/❌ | 正常結案 X 筆，有無退票/婉拒 |
   | 曝險比例 | ✅/⚠️ | 剩餘本金/本票額度＝X% |
   | 本次金額 | ✅/⚠️/未提供 | 本次 X 元 vs 歷史最大 Y 元 |
   | 第三方監控 | ✅/⚠️/❌ | sumto 燈號＋企業認證狀態 |
   | Drive 內部名單（若有檢查） | ✅/❌/未檢查 | 是否列在黑名單/風控名單 |

3. 結論：🟢/🟡/🔴 ＋ 一句話理由
4. 若為 🟡 或 🔴，列出具體「待覆核／待補件」項目清單

## 例外狀況

- 新客戶（無歷史案件）：固定標記 🟡，理由寫「首次往來，無歷史信用資料，
  建議依標準流程審查」，企業認證與 sumto 兩項照樣檢查並列入表格。
- sumto 剛加入監控、還沒有燈號資料：說明「今日新增監控，尚無燈號，建議
  明天再確認一次；若為急件，請以工商登記/法院查詢等其他管道人工確認」。
- Google Drive 未連接或找不到內部名單檔案：略過該項比對，不視為錯誤，
  也不需要跟使用者確認，其餘流程照常進行。
- 這個技能給的是**判斷建議**，不是最終核准依據，結論僅供快速分流參考，
  最終核准仍需人工簽核。
